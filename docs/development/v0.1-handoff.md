## Start on Windows

Node.js 22, Corepack, and the project-local PostgreSQL 16.16 and Chromium
binaries are available on the original Windows development machine. A new
checkout can follow the [native setup guide](native-postgresql.md). The Mac
procedure uses a PostgreSQL 16 installation and the same package scripts.

From the repository root:

```powershell
corepack pnpm install --frozen-lockfile
corepack pnpm db:local setup
corepack pnpm db:migrate
corepack pnpm db:seed
corepack pnpm dev
```

Open <http://127.0.0.1:5173>. The API listens on loopback port 3000. Press
Ctrl+C to stop the app and use `corepack pnpm db:local stop` to stop the
database. Use `corepack pnpm db:local start` for subsequent sessions.
The cluster data and generated credentials are local and ignored. Seeding
is idempotent. Browser and database tests use `archimesh_test`.

## Walkthrough

1. As **Architect**, search for **Supplier Intake**. Open **Supplier
   Onboarding**, then use its relationships or neighborhood to find
   **Supplier Harbor North**. Follow the first-class support relationship
   to inspect its Markdown and revision history.
2. Open **Saved views**, then **Procurement Solution Context** and
   **Model diagram**. The legend identifies existing and proposed
   connections. Move a node and save its layout to create a view revision.
   Open **Supplier and Order Data Responsibility** and switch to **Matrix**
   for data ownership and CRUD relationships.
3. In a writable workspace, create an object, validate and edit its
   YAML/Markdown, then inspect the previous version in **History**. Use
   **New relationship** to link permitted endpoint types. A relationship
   can also be the target of a project impact.
4. Open **Scenarios** and the proposed supplier integration activation.
   Compare the pinned draft to the future active proposal. Follow the
   actual record to verify its lifecycle remains draft.
5. Switch between **Procurement contractor** and **Integration contractor**.
   Compare accessible scopes and shared catalog results. The other project
   is unavailable even if you follow its saved URL.
6. Use the [CLI and MCP workflow](agent-tools.md) to find the same provider,
   retrieve its revision and support relationship, and save a draft reuse
   proposal. The workbench can display the resulting scenario.

See the [Alderfen Works model guide](demo-model.md) for the synthetic data.
The seed contains 126 canonical documents and a representative scenario.

The catalog defaults to the latest recorded revision. Use `recordedAt`
and `effectiveOn` for explicit, distinct historical lenses. An operational
lifecycle of retired can remain discoverable as knowledge. The repository's
**Retire** command removes the object from the live graph and keeps its
history. Proposal changes remain separate from live revisions.

OKF bundles retain stable object IDs and the exact canonical Markdown.
The manifest pins source revisions. Import creates new destination revisions
with trusted local authorship. An architect can import into a clean or
compatible model, with referenced objects in the bundle or already present.
The request limit is 1 MiB and at most 128 objects. Agent responses have
additional transport bounds. View membership is edited through the view Markdown.

## Verification

- Hosted foundation verification passed on Ubuntu, including the Docker build,
  and Windows with the native PostgreSQL smoke.
- Windows local verification used Node 22.22.3, pnpm 10.34.9 and PostgreSQL
  16.16. The locked install, formatting, lint, strict checks, production
  build and 33 source tests passed, with two live cases run separately.
- All 19 real PostgreSQL tests passed. Coverage includes inaccessible objects and relationships,
  historical reads, scope switching through pooled connections, rollbacks,
  stale writes, idempotency, viewpoint consistency, scenario isolation and
  OKF round-trip. All 7 Chromium tests passed and cover health, reuse, editing, proposals and
  contractor scope switching. The workbench was visually checked at desktop
  and narrow browser widths.
- All 12 local stdio tooling tests passed. They exercised real provider lookup, scoped search and a
  draft proposal against the isolated test database. Independent review
  tightened export size limits, database target guards and saved-view
  consistency. The runtime dependency audit found no high or critical advisories.
- Physical macOS, production identity and enterprise-scale throughput remain
  unverified. Tests include synthetic data only.

Run `corepack pnpm verify`, `corepack pnpm test:db` and
`corepack pnpm test:e2e` for the local gates. Install the pinned Chromium with
`corepack pnpm exec playwright install chromium` if needed. See the
[execution record](v0.1-execution.md) for evidence and decisions.
